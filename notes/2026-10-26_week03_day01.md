## 具体错误

### 第 2 题：子查询字段与外层条件不对应

初始答案在外层使用了 `city IN (...)`，而子查询返回的是客户所在城市。结果会按城市放大范围，把同城但没有已支付订单的客户也包含进来。

此外，`paid` 是字符串，必须写为 `'paid'`。

正确查询：

```sql
SELECT customer, city
FROM customers
WHERE customer_id IN (
  SELECT customer_id
  FROM orders
  WHERE status = 'paid'
);
```

结果：张三、李四、赵六、孙七、周八。

### 第 4 题：只写了 CASE 表达式，没有写完整查询

正确查询：

```sql
SELECT order_id,
       amount,
       CASE
         WHEN amount >= 200 THEN 'high'
         WHEN amount >= 100 THEN 'medium'
         ELSE 'low'
       END AS amount_level
FROM orders;
```

结果：订单 103、106 为 `high`；101、104 为 `medium`；102、105、107 为 `low`。

边界提醒：当前题目没有空金额。如果将来 `amount` 可能为 NULL，`ELSE 'low'` 会把未知金额归为 `low`；应按业务口径增加 `WHEN amount IS NULL` 分支。

### 第 5 题：空结果不等于所有订单都存在

```sql
SELECT order_id
FROM orders
WHERE status IS NULL;
```

本题返回空集，准确含义是“当前 7 笔订单的 `status` 都不是 NULL”。它不能证明订单都有记录，也没有检查空字符串。`status = NULL` 的比较结果是 UNKNOWN，因此不会选出 NULL 行。

## 掌握情况

已经独立掌握：

- 标量子查询必须返回单一值。
- `NOT EXISTS` 的相关子查询结构。
- NULL 必须使用 `IS NULL` 或 `IS NOT NULL`。
- CASE 分支按从上到下的顺序生效。

当前最薄弱：

- 子查询返回字段与外表条件的粒度和含义不稳定。
- 容易漏写完整的查询骨架。
- 会把“空结果”解释得超过 SQL 实际检查的范围。
